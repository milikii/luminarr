# Codex 3-round prompt

> 用途：给 Codex 的短批次连续推进提示词模板。
> 目标：默认连续推进 3 轮，每轮只做一个最小闭环；真实验证自己跑；除非遇到明确停止条件，否则不中途停下等确认。

## Prompt

```text
按仓库根目录 `AGENTS.md` 执行。

本机真实测试环境已就绪；Transmission / Emby 测试容器已启动，凡是任务需要真实 downloader / import / refresh 验证，直接执行，不要留给我。

本次会话默认连续执行 3 轮。除非出现以下任一情况，否则必须继续下一轮：
* **明确 blocker**：push 命令返回非零退出码且重试一次后仍失败；或依赖服务不可达且无法绕过。push 成功但无回显、网络延迟、输出不完整，均不算 blocker。
* **明确达到 `docs/NEXT_STEP.md` 当前主线 `Done when` 列出的可测量退出条件任一条**：满足后宣告当前主线完成；如果 `After this step` 已给出下一步，就切过去继续，不要因为“主线已完成”直接停止。
* **触发 `AGENTS.md` §11 的诊断分流递减停机线**：从第 2 轮起开始计数；连续两轮代码变更都 `< 20` 行、且都只是对同一个 repo 方法再拆 `if/elif/log` 诊断分支时，在第二个满足轮次结束后停止，并汇报“当前主线已到诊断分流递减停机线，请确认是否宣告主线完成”。
* **继续修改会违反 `AGENTS.md` 或当前文档边界**。

---

**如果某一轮结束后没有立刻看到下一步：**
* 不允许直接停止。
* 先重新扫描 `docs/NEXT_STEP.md` 相关段落、`docs/STATUS.md` 当前快照、相关代码和最近 3 个提交。
* 重新扫描的唯一目的是：从当前主线里找出一个比刚才更小、更保守的收口任务继续执行。找到则立即继续，不停下来等确认。
* 只有在完成这次重新扫描后，确实找不到任何可执行的收口任务，且仍满足上面任一停止条件，才允许停止。

---

**第 1 轮先做冷启动一致性检查：**
* **读取**：`AGENTS.md`、`docs/INDEX.md`、`docs/ARCHITECTURE.md`、`docs/NEXT_STEP.md`、`docs/DECISIONS.md`、`docs/STATUS.md`
* **运行**：`git log --oneline -20`
* **对比**：对比 `docs/STATUS.md` 与 `git log` 近 20 条是否一致。
* **核对**：核对 `docs/NEXT_STEP.md` 当前 `Done when` 可测量退出条件是否已满足；不要把旧主线的专用检查项硬套到新主线。
* **策略**：如果发现文档漂移，第 1 轮只补文档，不改业务代码。如果已满足当前主线任一退出条件，先宣告当前主线完成，再按 `After this step` 进入下一条主线；不要因为“主线完成”直接结束会话。
* **强制要求**：第 1 轮结束时，如果尚未完成任何真实代码或文档闭环并完成 commit / push，不允许停止，必须进入第 2 轮。

---

**第 2-3 轮不要机械重读全文。默认只读：**
* `AGENTS.md`
* `docs/NEXT_STEP.md` 当前主线相关段落
* `docs/STATUS.md` 当前快照
* 与本轮任务直接相关的代码、测试、最近 3 个提交
* 只有在当前任务碰到长期边界时，才按需读取 `docs/DECISIONS.md` 相关段落。
* 只有在需要看当前主线详细历史时，才按需读取 `docs/PERSISTENCE_CLOSURE_LOG.md`。
* 只有在需要核对 cleanup 已完成证据时，才按需读取 `docs/CLEANUP_VERIFICATION_WINDOW.md`。

---

**每轮流程固定为：**
1. 只选一个最小闭环任务。
2. 直接实施并自行验证。
3. 必要时更新相关文档。
4. review diff，确认没有 scope creep。
5. 从第 2 轮起，判断本轮 diff 是否触发诊断分流递减停机线。
6. commit 并 push；push 成功即视为状态确认完成，不因无额外回显而停止。
7. 如未触发停机线，立即开始下一轮，不要停下来等我确认。

---

**文档写作要求：**
* 不要把长台账再写回 `docs/STATUS.md`。
* `docs/STATUS.md` 只保留当前快照。
* 当前主线的详细闭环按 `docs/INDEX.md` §4 规则写回对应台账；若该主线明确要求合并进 `docs/PERSISTENCE_CLOSURE_LOG.md` 既有分组，就继续合并，不新开逐日小节。
* cleanup 已完成窗口的详细证据只写入 `docs/CLEANUP_VERIFICATION_WINDOW.md`。
* 不要在汇报里大段复述文档原文，只用 1-2 句中文概括当前真相。

---

**默认不要在每轮结束后给我固定总结，也不要逐轮重复汇报。只有在以下情况才中途汇报：**
* 失败或遇到 blocker。
* 必须由我决定。
* 触发诊断分流递减停机线（本轮即是最后一轮）。

**在全部轮次结束后，再统一做一次简短总结，只输出：**
* 当前主线完成度。
* 距离项目完全完成还需要多少百分比，本次推进了百分之多少。
* 本次主要完成了哪些闭环。
* 最后停下来的原因（3 轮结束 / blocker / 已达到可测量退出条件 / 诊断分流递减停机 / 文档边界）。

只有在失败、遇到 blocker、或必须由我决定时，才展开说明细节。
```

## Recommended use

- 新开会话时，直接把上面的 `Prompt` 整段贴给 Codex。
- 这份 3 轮模板适合“先看一轮冷启动，再做 1-2 个小闭环”的日常推进。
- 如果后续还想继续推进，再新开下一次 3 轮会话；交接时优先给 `最新 commit hash + docs/STATUS.md + 当前主线台账入口`，不要把旧线程全文继续叠上去。
- 如果你要跑长批次，把这里的轮数换成 5，或直接改用 `docs/CODEX_LOW_TOKEN_10_ROUND_PROMPT.md`。
